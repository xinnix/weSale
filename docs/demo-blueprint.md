# weSale 演示蓝本 — 拉新 → 标签 → Copilot 辅助 → 转化闭环

> 日期：2026-09-13。本文是面向演示的端到端链路对齐文档（demo blueprint），SSOT 产品定义仍为 `docs/prd.md` v2.0，实施进度台账见 `docs/ROADMAP.md`。
> 演示目标：把「扫码获客 → 语义化标签 → 企微侧边栏 Copilot 辅助 → 小程序下单转化 → 标签更新」串成一条可向客户/投资方完整演示的增长闭环。

## 决策记录（2026-09-13 对齐）

| 决策点       | 结论                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| 获客入口     | **双路径都要**：扫码进小程序（积分路径）+ 扫码加企微成员（活码私域路径）            |
| 积分触发     | **扫码注册即送**：新客扫码进小程序注册 → 立即入账欢迎积分（留存钩子，非消费后入账） |
| Copilot 深度 | **M2 含 AI 生成**：侧边栏不止画像与静态卡片，需 3 策略流式生成辅助话术              |
| 联调深度     | **真联调企微**：getCurExternalContact + sendChatMessage + 活码回调全部实测          |

## 一、演示流程（端到端链路）

```
① 获客（双路径）
   路径 A: 扫小程序码 → 带参落地 → 静默注册 → 欢迎积分入账 → 自动打渠道标签
   路径 B: 扫企微活码(add_contact_way + state) → 添加好友 → change_external_contact
           回调归因 → Contact.tags 自画像 + 企微原生 mark_tags 双写
        ↓
② 语义化标签
   Contact.tags：渠道标签(活码 state) + 行为标签(生命周期/消费推导)
    例：「来自包裹卡」「高意向」「已购」→ 侧边栏画像可直接读
        ↓
③ 运营中 Copilot（企微聊天工具栏 H5）
   Member(企微员工 OAuth2) → getCurExternalContact 定位当前客户
   → 画像 API(标签/积分/消费/最近 KF 会话摘要)
   → [M2] 3 策略并行流式生成话术建议(TTFT ≤ 1.5s)
   → sendChatMessage 一键发送(销售逐条确认，风控红线) + 复制兜底
   → [M4-lite] 产品 miniprogram 卡片选择后一键发送
        ↓
④ 转化更新
   顾客进小程序 → 下单 → JSAPI 支付 → Order PAID
   → 规则更新该顾客标签(「已购」等) + 积分入账
```

## 三、实施顺序（先竖切高风险点，再横铺）

1. **schema 四件套**：`Contact.tags`/`pointsBalance`、`PointsLedger`、`LiveCode`、`Member` → migrate
2. **侧边栏 M1 spike 先行**（真联调最大风险）：OAuth Member 身份 → `getCurExternalContact` → 画像 API → 文字/小程序卡片的 `sendChatMessage` 三端实测
3. **获客双路径**：路径 A（小程序带参落地 + 注册送积分）+ 路径 B（活码 F8 + 归因 + 双写标签）
4. **M2 AI 生成**：3 策略流式 + 画像/会话上下文组装 + 一键发送 + 复制兜底 + 发送事件上报
5. **转化标签**：订单 PAID 事后规则 → 更新 `Contact.tags`
6. **收尾**：端到端演示脚本 + 风控红线审查（全链路无静默/定时/批量自动发送）

## 四、风险与注意点

1. **路径 A 的「扫码」= 小程序码**：小程序生态外的带参落地只能用小程序码，不能用普通链接，物料设计需走小程序码
2. **纯扫码加的企微好友 V1 无会话上下文**（企微 API 限制）：侧边栏对他只有画像 + 产品目录，AI 建议基于画像生成；走过 KF 会话的顾客才带对话上下文 —— 演示脚本两类各准备一位
3. **M2 依赖 LLM 链路**：需确认 `LLM_*`/供应商配置就位；M1 壳应先不依赖 LLM 跑通，再叠 M2

## 五、验收标准（对应 ROADMAP Phase 2 验收，收窄到演示范围）

1. 路径 A：扫小程序码 → 欢迎积分入账 → 渠道标签可见
2. 路径 B：扫活码添加 → 归因渠道来源 + 自动标签双写（企微侧可见 + `Contact.tags`）
3. 侧边栏 `getCurExternalContact` 正确显示当前客户画像（标签/积分/消费/会话摘要）
4. [M2] 3 策略流式生成，TTFT ≤ 1.5s、完整 ≤ 4s；产品卡片可选择发送
5. 一键发送走 `sendChatMessage`，销售客户端内逐条确认；无绕过确认的自动发送
6. 顾客小程序下单 → 支付 PAID → 该顾客标签更新（如「已购」）
7. Member 身份无法访问 admin 路由与数据面
8. 端到端演示脚本可复演（mock 数据 + 真实链路）
